# clara_aws_integration (Resource)

Registers an AWS payer account with Clara once its AWS resources exist.

**Create-only.** The API key this provider uses can register an account and nothing else. So:

- **Plan and refresh** make no requests to Clara. The state is not compared with Clara, and drift is not detected.
- **A changed argument is refused** at plan time. Applying it could not update the integration, and replacing it would be refused as a duplicate.
- **Destroy only forgets the resource.** The integration stays in Clara. Disconnect it there if it should go. Nothing is deleted in AWS.
- **There is no import.**

## Example Usage

```terraform
module "clara" {
  source  = "nops-io/clara-onboarding/aws"
  version = "~> 0.1"

  providers = {
    aws           = aws
    aws.us_east_1 = aws.us_east_1
    aws.sharesave = aws
  }

  client_id       = "<clara-client-id>"
  cur_bucket_name = "<globally-unique-bucket>"
  permission_mode = "minimal"
}

resource "clara_aws_integration" "this" {
  payer_account_id = "123456789012"
  permission_mode  = "minimal"
  role_arn         = module.clara.role_arn
  external_id      = module.clara.external_id
  cur_bucket_name  = module.clara.cur_bucket_name
}
```

## Schema

### Required

- `cur_bucket_name` (String) S3 bucket that receives the Legacy CUR (and CUR 2.0).
- `external_id` (String, Sensitive) ExternalId from the role's trust policy. Sent to Clara, never returned by it.
- `payer_account_id` (String) 12-digit payer (management) account id.
- `permission_mode` (String) minimal (Savings Analysis) or full (Full Platform, Inform & Operate). Must match the role's attached policies.
- `role_arn` (String) ARN of the integration role created by the onboarding module. It must be a role in the payer account.

### Optional

- `cur2_export_name` (String) CUR 2.0 export name. Setting it turns CUR 2.0 on for the integration.
- `cur2_s3_prefix` (String) CUR 2.0 S3 prefix. When unset, Clara uses nops-cur2.
- `cur_report_name` (String) Legacy CUR report name. When unset, Clara uses nops_cur_<client id>_hourly.
- `cur_s3_prefix` (String) Legacy CUR S3 prefix. When unset, Clara uses nops-cur.
- `name` (String) Name shown in Clara. Defaults to "AWS Account <id>".

### Read-Only

- `failed_checks` (List of String) Permission checks that failed at creation. Empty when everything passed.
- `id` (String) Clara integration id.
- `status` (String) Integration status when it was created: active, validating or awaiting_customer_setup. It is not refreshed.
- `verification_message` (String) Why the role could not be assumed, when that was the failure.
- `verification_state` (String) Result of Clara's access check at creation: verified, partial (Savings Analysis checks failed but cost and usage ingest works), failed, or unavailable (the check could not run). It is not refreshed.

Attributes are recorded when the integration is created and are not refreshed.

## When verification does not pass

The integration exists in Clara once the call succeeds, so a failed check is a **warning**, not an error. Failing would taint the resource, and the
next apply would be refused because the account is already connected. Check `verification_state`, then open the integration in Clara to see
which checks failed and verify again.

## Already onboarded

If the payer account already has an integration, create fails with a message saying so. The key cannot adopt or change it. If the account was
onboarded on purpose, remove the resource from the configuration. If it is a leftover, disconnect it in Clara first.
